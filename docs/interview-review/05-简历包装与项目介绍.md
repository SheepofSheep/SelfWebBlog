### 30 秒版本

“这是一个 Spring Boot、Vue 3 和 SQLite 的个人博客，除了文章管理，还有 GitHub 登录、评论审核、点赞和图片资源管理。后端重点是 Cookie JWT 的版本撤销、数据库约束与事务保证点赞一致性，以及图片删除的补偿恢复。目前是单实例设计，没有高并发数据。我的具体负责模块是【本人确认后补充】。”

### 1 分钟版本

“项目是前后端分离的个人博客，后端 Spring Boot 配 MyBatis-Plus 和 SQLite，前端 Vue 3。业务包括文章草稿、发布和归档、标签、评论留言审核、用户与 GitHub 登录，以及站点和图片管理。

我会重点介绍三个实现：认证把 JWT 放在 HttpOnly Cookie，写请求校验 CSRF，并在请求时检查数据库 tokenVersion 和角色；点赞用唯一约束、实际影响行数和事务内 SQL 计数，重复请求不会重复加一；图片删除先暂存并留下清单，再按事务结果完成或恢复。

项目还有 Flyway、测试和 CI。它适合当前单实例规模，没有 Redis、消息队列或性能压测成果。审查也发现旧评论接口可见性和管理员密码轮换需要完善，我会把这些作为未修复边界讲清楚。我的实际贡献是【本人确认】。”

### 3 分钟版本

“这个项目是一个个人博客，用来提供文章阅读和后台内容维护。前端是 Vue 3、Router 和 Vite，后端是 Spring Boot 3，数据访问结合 MyBatis-Plus、注解 SQL 和 JdbcTemplate，数据库是 SQLite，图片保存在本地。选型降低部署组件数量，适合个人站点；它也带来单写者和本地存储边界，最初的选型过程需要按我的真实经历说明。

业务上，文章支持草稿、发布、归档和标签管理，发布时间独立于创建时间。写作页有本地草稿，图片上传完成后替换临时地址，未完成时阻止保存。评论和留言通过统一目标模型表示，回复归属根评论，后台可以审核、置顶和调整顺序；公开列表批量读取用户资料，避免逐条查询。我的实际负责范围是【本人确认后填入】，没有参与的部分我只介绍源码理解。

后端认证使用 Cookie JWT。签名校验后仍查用户，比较 tokenVersion，并使用数据库当前角色。退出清 Cookie 同时增加版本，因此旧 Token 到期前也会失效，代价是每请求要查库，而且影响该用户所有旧版本会话。Cookie 自动携带，所以还使用双提交 CSRF。GitHub 授权回调验证 state，用 code 获取第三方身份，再用短期一次性 ticket 回到前端兑换本站会话；没有把长效 JWT 放 URL，也没有 refresh token。

一致性方面，点赞接口表达最终想要的状态。数据库唯一键限制同用户同目标只有一条，只有 INSERT 或 DELETE 真正影响记录时才调整 count，两者在同一事务里。这比前端按钮限制更可靠。SQLite WAL 允许读写共存，但只有一个写者，一些业务先取得写锁；我不会把它称作 MySQL 行锁或宣称已支持多少并发。

资源管理更需要区分数据库和磁盘。图片有格式与尺寸验证、WebP 派生和 hash 复用；删除前检查草稿、归档和站点引用，先暂存文件并写清单，事务结束后完成删除或回滚恢复，重启也尝试处理遗留状态。它是补偿和恢复设计，不是文件自动参加数据库事务。

工程上有 Flyway 迁移、迁移前数据库快照、请求 ID、安全审计及测试/CI。不过仓库不能证明生产 HTTPS、监控、备份恢复演练和性能收益。本次审查还发现配置管理员密码变化没有撤销数据库旧密码、旧评论读取遗漏根可见性，以及孤立图片再上传冲突。优化会先修这些正确性问题，再减少全量查询，最后按实际增长考虑迁库或共享存储。相关修复尚未实施，真实开发困难和故障经历由本人补充。”

## 5. 容易暴露理解不足的面试风险

| 已使用技术 | 最容易说错 | 最低应能解释 |
| --- | --- | --- |
| Spring Boot | starter 自动实现所有业务；所有 Bean 都安全 | 条件装配、构造器 DI、扫描和 Bean 生命周期 |
| Transactional | 文件自动回滚、自调用一定有效 | 代理调用、异常规则、连接线程绑定、事务范围 |
| JWT | 加密、无需查库、退出只删 Cookie | 签名、过期、版本、数据库角色、撤销范围 |
| OAuth | state/code/ticket/access token 混称 | 各自用途、一次消费、稳定 ID、同名不能自动绑定 |
| SQLite | WAL 无锁、等同 MySQL 行锁 | 单写者、快照、busy_timeout、方言与迁移 |
| BCrypt/AES-GCM/HMAC | 密码可解密、Base64 是加密、IP 完全匿名 | 密码慢散列、nonce、MAC、可关联性、密钥管理 |
| MyBatis-Plus | null 赋值一定写库、自动防所有注入 | 更新策略、绑定参数、动态语法白名单 |
| Vue | 只是模板；路由保护就是权限 | Proxy/ref、computed/watch、异步失效、后端授权 |
| CI/测试 | 目录存在就全量通过、测试数量等于覆盖率 | 单元/mock/集成/E2E 的证明边界，CI 不等于 CD |
| Linux/Nginx/性能 | 没做也照模板写 | 仓库无部署证据，缺测量就是待验证 |

## 6. 项目成熟度与求职定位

**评价**：它已超过最小 CRUD 博客，具备实际状态规则、约束、隐私和恢复设计，适合作为 Java 后端实习项目深入讲解。尚不能据仓库称为经过线上验证的高可靠或高并发系统：兼容接口策略不统一、输入模型与大服务维护性不足、几个核心边界缺陷未修复，真实部署、容量、恢复和个人责任证据缺失。

优势是完整前后端链路、可追踪的安全与一致性实现、有意义的 SQL 和测试。短板是实习核心 Java/Spring/数据库知识很容易被深入追问，框架调用与理解程度需要补齐；项目规模不能替代问题分析质量。
