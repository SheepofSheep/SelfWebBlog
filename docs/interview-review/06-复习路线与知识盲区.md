## 3. 知识盲区：实现、库能力与未来方案

| 层次 | 项目内容 | 该怎样表述 | 需要补的理解 |
| --- | --- | --- | --- |
| **源码证实的应用逻辑** | JWT claims/版本检查、CSRF Cookie 头、授权注解、OAuth ticket | “项目实现这条流程，个人负责范围待确认” | 生命周期、边界及实际失败条件 |
| **源码证实的业务规则** | 状态机、点赞 affected rows、置顶顺序、批量资料、标签同步 | “规则和约束是……” | 并发与不变量如何共同保证 |
| **源码证实的资源治理** | 引用宽限、文件暂存、恢复清单、事务回调 | “有补偿恢复，不是跨资源原子事务” | 崩溃点、恢复幂等及剩余缺口 |
| **调用库的能力** | Spring IoC/AOP/自动配置、MP mapper/ID、BCrypt/JJWT、Guava、ImageIO | “使用其 API，底层由库提供” | 不求手写框架，但能解释关键机制和配置影响 |
| **前端实际能力** | ref/reactive、computed/watch、fetch、代数失效、点赞队列、草稿 | “当前就是这些实现，没有 Pinia/Axios 拦截器” | 响应式与异步、权限与体验的区别 |
| **尚未实施** | refresh token、Redis、MySQL、消息队列、微服务、分布式锁、对象存储、FTS | “这是有条件的未来方案” | 何时需要、引入何种新问题 |
| **未证实运维经历** | Linux/Nginx/TLS/CD、告警、周期备份、线上性能与故障 | “待验证 / 待本人确认” | 用配置和运行证据补，不能借模板填空 |

“用了库”不等于“没有技术含量”，也不等于“理解底层”。实习面试更看重能否解释输入、输出、约束、失败与权衡。

## 4. 高风险盲区与最小补课动作

1. **事务**：不看稿说出代理、自调用、异常、线程绑定；拿 Tag 外层事务反驳“自调用就整个事务无效”。
2. **JWT**：画原 Token 被复制、logout 版本变化后的结果；说明全用户旧会话撤销与无 refresh。
3. **SQLite**：画一个读者快照、一个写者和第二个等待写者；确认不是行锁；把 timeout 与正确性区分。
4. **数据库约束**：指出点赞唯一键、置顶部分索引和触发器分别拦什么，哪些跨表规则仍由 Java 保证。
5. **OAuth**：遮住时序图说完 state→code→第三方 token→本地用户→ticket→本站会话；说明用户名碰撞不能自动合并。
6. **加密术语**：分别举密码、IP 密文、IP HMAC 和文件 SHA256 的用途；nonce/盐/secret 不能混用。
7. **前端过期与乱序**：解释为何 requestId 不等于 abort、401 不等于 403、路由跳转不等于授权。
8. **测试证据**：准确说“77 前端单测和此前 3 个 MVC 测试通过”，不扩展成全量通过或覆盖率。
9. **部署**：把实际知道的本地端口与代理讲清；不补造域名、证书、服务器和进程管理。
10. **个人经历**：能拿出本人实际改过的一段代码并独立解释；未知项保留未知，不写并不存在的故障故事。

## 5. 最可能被连续追问的 10 个问题

1. JWT 为什么还查数据库？退出影响一个设备还是所有旧会话？
2. 管理员环境密码变了，旧数据库密码为何还可登录？
3. HttpOnly、SameSite、CSRF、CORS 分别防什么，XSS 还能做什么？
4. state、code、GitHub access token、ticket、本站 JWT 有何区别？
5. Transactional 自调用、捕获异常和 IOException 会怎样？
6. 重复点赞与超时重试为什么不多计数，数据库哪条约束兜底？
7. SQLite WAL 为什么仍只有一个写者，连接池增加有什么代价？
8. 根评论隐藏后为什么旧接口还能查到回复，如何统一规则？
9. 图片文件不在 JDBC 事务中，崩溃后怎么恢复，哪里仍有风险？
10. 全量查询和 mock E2E 的边界在哪里，你的个人贡献有哪些证据？

## 6. 学习完成标准与下一步

达到实习面试准备标准：可以一分钟讲项目；独立画认证/点赞时序；准确定位五个源码问题；能解释 TOP 20 中的机制及至少一个取舍；能够回答 03 文档的基础和核心题，而不是把推荐答案逐字背出；每条简历内容有个人经历佐证。

最值得先投入的学习任务是 **从源码讲通认证和点赞两条链路**：它们集中覆盖 Java、Spring、SQL、事务、HTTP 与安全。接着研究 R01/R02 的小范围修复与隔离回归；本次并未实施。随后才考虑查询数据量和备份恢复，优先于新增中间件或更换技术栈。
