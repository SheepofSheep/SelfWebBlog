# 个人博客全栈重构设计

日期：2026-07-26

## 1. 目标

在保留现有公开阅读、访客账号、互动、写作和后台管理能力的前提下，删除旧前端代码并重新构建界面与交互体系，同时整理和优化后端边界。

新前端采用圆润、液态玻璃、内容优先的个人博客风格。视觉表达来自排版、封面、曲线和交互，不使用模板化宣传口号、虚构文章、虚构统计或带有明显生成式文案风格的占位内容。

## 2. 已确认的设计方向

采用“A · 流动书页”方向：

- 非对称、编辑式、内容优先的首页布局。
- 圆润液态玻璃表面，但不把每块内容都包进卡片。
- 曲线光带贯穿首页和页面过渡，不遮挡内容或交互区域。
- 支持亮色和暗色主题。
- 支持页面动效、主题切换动画和可关闭的鼠标拖尾。
- 文章卡背景由真实文章封面或博主配置决定，不使用固定示例内容。

## 3. 旧前端处理策略

采用替换式重构，不在现有界面上小修小补。

- 删除 `blog-frontend/src` 内旧页面、旧组件、旧样式、旧状态与旧 UI 工具。
- 不保留新旧两套组件、兼容样式表或旧页面入口。
- 重新建立应用外壳、路由页面、功能模块、共享组件、API 客户端、状态与设计令牌。
- 原有 API 行为仅作为业务契约参考；客户端代码重新整理，不直接继承含义混乱的旧模块边界。
- 重写仍有价值的纯业务测试，不让测试绑定旧组件结构。
- 保留 Vite/Playwright 等必要工程配置，并按新结构调整。
- 保留 `public` 中仍被业务使用的真实图片、表情和站点资源；删除确认无引用的旧装饰资源。
- 不删除后端、数据库、上传文件、文章、用户、评论、标签或媒体记录。
- 当前工作区未提交的旧前端改动属于删除范围；后端未提交改动需逐项审查后再决定合并或替换。

## 4. 信息架构

### 4.1 公开阅读区

- 首页：精选文章、最新文章、文章流、筛选搜索、作者入口和必要站点信息。
- 内容发现：文章归档、标签、内容日历和全站搜索。
- 文章阅读：正文、目录、阅读进度、浏览量、点赞、分享、评论和回复。
- 互动：留言板、验证码、防刷限制、回复与置顶展示。
- 站点资料：关于页、作者经历和外部链接。
- 访客账号：注册、账号登录、GitHub 登录、头像和个人资料。

主导航只显示：首页、文章、归档、留言、关于。标签和日历从文章发现区域进入；搜索、外观和账号位于右侧工具区。

### 4.2 博主工作区

- 概览：文章、互动、用户和资源状态。
- 内容：文章列表、草稿、批量操作和标签管理。
- 写作：Markdown 编辑、实时预览、图片粘贴与资源、草稿恢复、封面和文章背景设置。
- 互动管理：评论和留言审核、回复、点赞、置顶、删除及批量处理。
- 用户管理：账号、称号和异常账号处理。
- 媒体库：上传、扫描、优化版本和安全删除。
- 站点设置：作者资料、链接、主题默认值和动效默认值。
- 安全审计：登录和敏感操作记录。

公开端和工作区共用设计令牌与基础控件，但使用不同应用外壳。工作区允许更高信息密度，不强行套用公开阅读布局。

## 5. 内容与文案规则

- 文章标题、摘要、封面、分类、标签、作者资料、站点信息和统计全部来自真实数据或后台配置。
- 前端不得内置示例文章标题、宣传口号、虚构指标或情绪化占位文案。
- 固定可见文字仅用于必要的操作、状态、字段名和导航，例如“搜索”“保存”“发布”“评论”。
- 标题为空时不自动补充“无标题”等可见文案。
- 无标题但有正文的文章，在列表中使用正文首段作为主要内容预览。
- 仅含图片的文章直接展示第一张正文图片和发布日期，不生成替代标题。
- 必要的无障碍名称可以使用日期和操作目的生成，但不作为装饰性可见文案展示。

## 6. 视觉系统

### 6.1 设计令牌

建立统一令牌：背景、玻璃表面、文字、弱化文字、边框、强调色、语义色、阴影、模糊度、圆角、间距、层级、动效时长和缓动。

亮色与暗色主题共享层级规则。暗色模式不简单反色，需为玻璃边缘、代码块、图片遮罩和阴影分别定义合适值。

### 6.2 容器规则

- 页面使用开放布局、内容带、列表、阅读画布和少量有目的的玻璃面板。
- 避免嵌套卡片、默认 Bento 网格和无意义的圆角容器堆叠。
- 文章阅读区保持稳定行宽和排版，不让持续动画影响长文阅读。

### 6.3 文章背景

精选文章和重点文章卡支持四种模式：

1. 跟随封面：完整使用真实封面，自动生成低饱和遮罩、玻璃折射和文字安全区。
2. 自定义：博主可设置背景图片、纯色、双色渐变和图片焦点位置。
3. 站点默认：使用站点主题色板和文章分类色。
4. 关闭背景：使用普通内容表面。

系统必须保证文字对比度。移动端可降低背景细节，但不得改变文章的视觉身份。

## 7. 动效系统

- SVG 曲线路径和渐变光带用于首页节奏与页面过渡。
- 页面进入、列表出现、封面切换、弹窗、导航和交互状态使用统一时长与缓动。
- 文章页仅保留轻微封面视差、阅读进度和操作反馈。
- 鼠标拖尾为柔和流体粒子或短曲线，仅在精细指针设备启用。
- 触屏、页面失焦、系统要求减少动态效果或用户关闭动效时停用鼠标拖尾。
- 外观设置可分别控制主题、页面动效和鼠标拖尾。
- 动画必须随页面生命周期清理，不能残留监听器、计时器、Canvas 或动画帧。

## 8. 日夜主题切换

- 在浏览器首次绘制前恢复已保存或系统主题，避免闪白。
- 支持从主题按钮位置扩散的圆形 View Transition。
- 不支持 View Transition API 的浏览器使用短时颜色过渡。
- 玻璃表面、阴影、曲线、代码块、图片遮罩和鼠标拖尾同步换色。
- 切换期间不阻塞滚动或点击；连续切换只保留最新状态。
- 启用“减少动态效果”时不播放扩散动画。

## 9. 写作模块

### 9.1 布局

- 桌面端使用编辑与预览双栏。
- 移动端使用编辑/预览切换。
- Markdown 编辑、草稿恢复、资源选择、封面设置和发布设置属于同一写作工作流。

### 9.2 图片粘贴

1. 用户从剪贴板粘贴图片。
2. 前端立即创建本地对象地址并在编辑区及预览区显示。
3. 上传任务进入队列并显示进度。
4. 上传成功后只替换对应占位内容为正式响应式图片标记。
5. 上传失败保留本地预览和正文位置，允许重试或移除。
6. 页面卸载时释放不再使用的对象地址；未完成内容进入草稿恢复流程。

拖放图片与资源库插入复用同一上传任务模型。

### 9.3 发布规则

- 标题、标签、分类、摘要和封面均可为空。
- 只有正文文字可以发布。
- 只有正文图片或其他有效媒体可以发布。
- 仅当正文既无文字也无有效媒体时阻止发布。
- 前后端使用相同的“有效内容”语义和测试用例。

## 10. 标签模块

- 写作页只保留一个可输入的标签栏。
- 输入任意文字并按回车后创建或选择标签。
- 已存在标签直接复用，不创建重复记录。
- 标签规范化包括去除首尾空格、拒绝纯空白并按不区分大小写方式去重；标签可包含一般文字和中文。
- 输入法组合期间不得误触发提交。
- 标签创建、文章关联和文章保存位于同一事务边界。
- 标签数据同步用于写作提示、全站搜索、文章筛选、标签目录和后台标签管理。
- 后台标签管理保留重命名、合并和删除能力，但使用同一份规范化标签数据。

## 11. 评论与留言

- 每条互动显示头像、昵称、称号、时间和允许公开的地区信息。
- 称号名称和样式来自后台用户配置。
- 一级操作只展示“点赞”和“回复”。
- 点赞使用乐观更新，失败后恢复原状态。
- 回复默认折叠并显示数量；展开后显示一层回复列表和输入框。
- 回复只保持一层视觉层级，避免无限缩进。
- 置顶和删除收纳在三点菜单中，并根据当前用户权限显示。
- 管理端沿用同一互动结构，增加审核状态、筛选和批量处理。
- 创建、回复、点赞、置顶、审核和删除都必须在服务端执行权限校验和防刷策略。

## 12. 前端架构

新前端按职责组织：

- `app`：应用启动、路由、公开端外壳和工作区外壳。
- `pages`：路由级组合页面。
- `features/content`：文章发现、归档、标签、日历和阅读。
- `features/editor`：编辑器、上传任务、预览和发布设置。
- `features/interaction`：评论、留言、点赞、回复和管理。
- `features/auth`：注册、登录、OAuth 和会话恢复。
- `features/admin`：工作区各业务面板。
- `shared/api`：规范化 API 客户端、错误模型和请求协调。
- `shared/ui`：按钮、输入、对话框、菜单、通知和空状态。
- `shared/motion`：曲线、页面过渡、主题过渡和鼠标拖尾。
- `shared/styles`：设计令牌、基础排版、Markdown 和主题。

路由页面只负责编排，业务状态位于功能模块，共享 UI 不依赖具体业务。

## 13. 后端架构优化

### 13.1 API 边界

- 前端统一调用 `/api/...`。
- GitHub OAuth 浏览器回调保留必要的非 API 跳转路径。
- 分离站点资料、当前访客资料和作者管理资料，停止让含义模糊的 `profile` 接口承担多个领域。
- 为首页提供明确聚合接口，返回作者摘要、精选文章、文章流、标签摘要和必要统计。
- 评论和留言统一进入互动领域，通过目标类型区分；清理新前端不再使用的旧评论客户端和重复控制器路径。

### 13.2 服务边界

- 拆分过大的认证控制器为账号认证、GitHub OAuth 和会话管理流程。
- 控制器只处理参数、权限入口和响应转换。
- 发布规则、标签同步、互动权限、图片引用和站点配置由服务层负责。
- 数据库访问集中到明确的 Mapper/Repository，响应使用专用 DTO，不直接暴露持久化实体。

### 13.3 数据与性能

- 通过 Flyway 增加文章背景模式、背景值和焦点位置等字段。
- 为发布文章排序、互动审核、日历查询和安全事件补齐复合索引。
- 首页聚合数据和站点配置使用短时缓存及条件响应；文章发布和站点修改主动失效。
- 所有列表使用统一分页上限。
- 保留 SQLite、Flyway、WAL 配置和迁移前备份机制。
- 不拆分微服务，不删除或重新初始化现有数据。

## 14. 数据流与错误处理

- API 请求支持取消、读请求去重和过期响应保护。
- 页面切换后旧请求不得覆盖新页面数据。
- 加载失败在对应内容区域提供重试。
- 保存、删除等变更操作使用简短通知；可修复的字段错误定位到具体控件。
- 图片上传使用有身份的任务状态，确保乱序完成时仍替换正确位置。
- 评论等乐观更新保存回滚快照。
- 后端返回一致的业务错误结构和正确 HTTP 状态。
- 标签关联、文章保存和必要资源引用更新使用事务。

## 15. 可访问性与响应式

- 所有核心流程支持键盘操作、可见焦点和合理的焦点回归。
- 图标按钮提供可访问名称；对话框和菜单正确管理焦点及 Escape。
- 颜色对比、文章排版和表单错误满足常见可访问性要求。
- 支持桌面、小型笔记本、平板和手机布局。
- 触屏端不依赖悬停，不启用鼠标拖尾。
- 尊重 `prefers-reduced-motion`。

## 16. 验证策略

当前基线：前端 32 项单元测试通过并可生产构建；后端 69 项测试通过。

新增验证包括：

- 发布有效内容判断：正文、图片、混合内容和全空场景。
- 粘贴图片即时预览、上传成功替换、失败重试和乱序完成。
- 标签创建、复用、规范化、输入法行为和事务回滚。
- 评论称号、点赞回滚、回复展开、权限菜单和审核。
- 主题首次恢复、连续切换、动画降级和减少动态效果。
- 数据库迁移、索引和关键 API 集成测试。
- Playwright 覆盖公开阅读、注册登录、写作发布、标签同步、评论互动和后台管理。
- 浏览器验证桌面、移动端、亮暗主题和键盘流程。
- 最终对照批准的视觉概念和浏览器截图检查文案、布局、字体、色彩、玻璃效果、封面、曲线、间距、图标和响应式行为。

## 17. 非目标

- 不引入微服务。
- 不更换数据库。
- 不增加与个人博客无关的营销页面或虚构功能。
- 不增加强制文章元数据。
- 不保留旧前端作为可切换主题或兼容页面。
- 不以静态设计截图替代真实可交互界面。

## 18. 完成标准

- 旧前端表现层已删除，新结构覆盖全部现有功能。
- 页面没有示例文章、模板口号、虚构统计或无意义说明文字。
- 写作、标签、评论和主题切换满足本规格的新增行为。
- 前后端接口边界清晰，重复路径和重复职责得到整理。
- 既有数据可迁移且不丢失。
- 单元、集成、端到端和生产构建验证通过。
- 桌面与移动端均达到批准视觉概念的实现质量，核心交互真实可用。
