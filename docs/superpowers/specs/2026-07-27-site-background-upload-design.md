# 站点背景上传设计

## 目标

在后台“站点内容”中为背景地址增加与头像上传一致的文件选择入口。用户选择图片后，系统上传并自动回填背景地址；只有点击现有“保存”按钮后，背景才写入站点配置并同步到公开页面。

亮色模式切换动画不在本次范围内，保留用户已经验收的现状。

## 交互设计

- “上传背景”按钮放在“背景地址”字段标题区域，与地址输入框形成一组。
- 选择图片后按钮显示“上传中…”，上传期间禁止再次选择背景和提交站点表单。
- 上传成功后把返回的原图地址写入背景地址输入框，并展示横向缩略预览。
- 成功提示“背景已上传，保存后生效”；用户仍可编辑地址或放弃本次修改。
- 点击现有“保存”后通过站点设置接口持久化，并立即同步公开页面背景。
- 上传失败时保留原背景地址并显示既有通知；文件输入始终清空，允许再次选择同一文件。
- 背景地址仍支持手工输入，上传按钮只是快捷入口。

## 技术方案

- 前端复用受管媒体上传接口 `POST /api/upload/image`，读取返回对象的 `originalUrl`。
- 不复用头像接口 `/api/upload/avatar`：该接口会立刻更新头像配置，而且返回数据结构和媒体管理链路不同。
- 上传图片继续进入媒体管理；站点保存后，现有引用扫描通过 `blog_info.bg_url` 识别其引用状态。
- `SitePanel.vue` 使用独立的 `backgroundInput` 和 `backgroundUploading` 状态，避免把上传过程误显示为“保存中”。
- 不新增数据库字段或后端接口。

## 约束与错误处理

- 沿用现有图片上传限制：管理员权限、CSRF、最大 10MB、最大 6000 × 6000，支持 JPG、PNG、GIF、WebP。
- 上传失败不修改 `site.bgUrl`。
- 上传中禁止保存，避免保存旧地址与新上传并发竞争。
- 组件销毁后不提交已经过期的上传结果。

## 测试

1. API 单测验证背景上传使用 multipart `POST /api/upload/image`，不手动设置 `Content-Type`。
2. 端到端测试验证“上传背景”按钮存在，选择文件后地址自动回填。
3. 端到端测试验证保存请求包含新 `bgUrl`，保存后公开背景同步。
4. 端到端测试验证上传失败时旧地址不变，控件恢复并可重试。
5. 运行前端单元测试、格式检查、构建和完整 Playwright 回归，再使用真实浏览器检查桌面与移动端布局、控制台和交互。
